# corpus-claim-audit

质性论文修订前的语料实证核验流程（WorkBuddy / Claude Code 风格 Skill）。

当论文基于语料库（访谈、评论、回答、田野笔记等）且收到审稿意见需要修改时，本 skill 提供一套**先核验、后动笔**的工作流：用数据把审稿人能攻击的每一个经验断言变成可复核事实，再进行批量修订。

## 触发场景

- 审稿人质疑量化表述（如"仅出现一次""反复出现"）缺乏系统依据
- 需要验证文中每条引语真实存在于语料
- 需要统计词频 / 覆盖率来回应"体裁效应""样本覆盖"等替代解释
- 需要对 docx 稿件做批量精确修订

## 工作流概览

1. **重建语料**：读取原始语料（xlsx/csv/txt），按论文 Methods 声明的口径（如 MD5 去重）重建语料库，核对单元数与论文声明是否一致。
2. **三类必跑审计**：
   - 量化断言核验：对"exactly one / repeatedly / pervasive / rare"等频率措辞做全语料词根检索，逐条分类真命中与误中；
   - 引语存在性核验：每条直接引语回搜语料，0 命中项必须改写，绝不允许语料里没有的话留在引号里；
   - 覆盖率 / 词频分布：按主题词集统计覆盖率，支撑或如实限定"覆盖全部语料"类声明。
3. **docx 批量精确修订**（python-docx）：逐段编辑保留样式，锚点匹配、命中报告、全量导出复核、difflib 逐段 diff 确认只含预期改动。
4. **交付三件套**：修订稿 docx（版本号递增）+ 检索报告 txt（供 rebuttal 出示）+ 待确认清单（只留作者能确认的事实，不编造）。

## 红线

- 审稿人建议与数据冲突时，按数据写更诚实但仍能回应质疑的论证。
- AI 披露、伦理审批类声明只能由作者确认，起草时标注 ★ 提醒。
